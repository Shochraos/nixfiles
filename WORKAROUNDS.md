# Workaround maintenance

Recheck these against the locked dependency sources when updating inputs. A clean evaluation does not prove that a native patch compiles or a hardware workaround is unnecessary. No upstream issue number is recorded where none has been verified.

| Location | Reason and verification | Removal condition |
| --- | --- | --- |
| `modules/features/ai/harness.nix` | Hermes unconditionally adds a patchelf 0.19.2 patch while the shared nixpkgs supplies 0.15.2. The package override removes only that named patch from Hermes' 0.15.2 build tools, preserving other patches and versions. | The locked Hermes package handles patchelf 0.15.2 without the override. Verify its runtime tools and Desktop package before removal. |
| `modules/base/nix.nix`, `assets/build-support/sphinx-hook.sh` | The pinned Sphinx hook loses builders in structured-attribute arrays. The local hook handles scalar, array and space-packed array forms. | The locked upstream hook handles all three forms and produces every declared documentation output without the overlay. |
| `modules/features/backup.nix`, `modules/graphical/sync.nix` | Their Sphinx pre-install hooks assume static files that newer Sphinx no longer provides. | The locked package hooks remove the static directory without relying on obsolete individual filenames. |
| `assets/patches/quickshell-hyprland-ipc-reconnect.patch` | Retry missing socket directories, failed status requests and event-socket disconnections for the current compositor signature. Build the patched package to verify compilation. A missing signature remains a launch-environment error; do not guess another compositor instance. | The locked Quickshell source provides equivalent startup and reconnect behavior. Test unavailable-at-start and disconnect/reconnect before dropping it. |
| `assets/patches/xdph-screencopy-buffer-reuse.patch` | Portal 1.5.0 already handles callback reentrancy, avoids out-of-buffer renegotiation and guards DMA-BUF allocation/planes. The remaining local delta bounds screen/window buffer recovery to ten retries with exponential backoff capped at one second, then reports exhaustion to PipeWire. Upstream workspace recovery and timer lifetime/generation guards are retained. | The locked portal supplies equivalent bounded screen/window recovery and terminal errors. Verify strict patch applicability and native compilation; test transient recovery and exhaustion in a separately approved runtime session. |
| `assets/patches/keepassxc-classic-theme.patch` | KeePassXC 2.8.0 Classic mode uses the bright palette Light role for the unlock panel, and standard dialog icons bypass adaptive recoloring. The patch uses AlternateBase and adaptive Unlock/Close icons. | The locked source supplies equivalent panel and icon behavior. Check strict patch applicability, compilation and Classic-mode appearance before removal. |
| `modules/graphical/plymouth.nix` Plymouth substitutions | Keep the configured spinner appearance through package rendering. | The selected upstream theme supports the same appearance without source substitutions. Compare the rendered theme before removal. |
| `modules/hosts/azazel/config.nix` NVMe APST override | Azazel retains `nvme_core.default_ps_max_latency_us=0` by explicit host policy; the affected device/firmware fault has not been established in this audit. | `pkgs/rea/python.nix` | Optional Python backends need pwntools, pyelftools and unicorn rather than a bare interpreter. The package wrapper selects this environment. | The locked REA package supplies these backends itself, or the owner explicitly drops their support. Recheck the local version overrides when updating Python. |
| `pkgs/{rea,irony-mod-manager,mp3tag,bscpylgtv}` | These package recipes are maintained in this repository. REA also retains its Ghidra and Java runtime dependencies. | Equivalent maintained packages in the locked nixpkgs satisfy the runtime and integration requirements. Compare behavior before switching sources. |

SteamVR retains `cap_sys_nice=p`. The boot and install/update path-triggered helper uses an open file descriptor, rejects symlinks and incorrect ownership, checks the current capability and verifies changes. There is no periodic fallback timer. This intentionally delegates the capability to the configured user's user-controlled SteamVR launcher; descriptor and ownership checks do not make that executable root-controlled. A SteamVR runtime test still requires the headset and the user's approval.
